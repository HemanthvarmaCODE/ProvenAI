## 3. Environment Configuration

The system uses a root `.env` configuration file. A template is provided in `env.example`.

Create `.env` in the project root:

```env
# ==============================================================
# ProvenAI Environment Variables
# ==============================================================
PROJECT_NAME=ProvenAI
SECRET_KEY=provenai-super-secret-jwt-key-change-in-production-2026-secure
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60
AES_KEY_HEX=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
DATABASE_URL=sqlite:///./storage/provenai.db
UPLOAD_DIR=./storage/uploads
WATERMARKED_DIR=./storage/watermarked
KEYS_DIR=./storage/keys
ATTACKED_DIR=./storage/attacked
CORS_ORIGINS=["http://localhost:3000","http://localhost:5173","http://localhost"]
```

> **Security Note:** In production, replace `SECRET_KEY` with a cryptographically generated 256-bit secret (`openssl rand -hex 32`) and `AES_KEY_HEX` with a dedicated 64-hex-character AES key.

## 4. Database Setup

ProvenAI utilizes SQLite with SQLAlchemy ORM. Database schemas and storage folders are initialized automatically on backend startup.

To manually re-initialize or reset the database cleanly:

```powershell
# Optional reset (cleans storage and re-creates empty tables)
Remove-Item -Force -ErrorAction SilentlyContinue ./storage/provenai.db
python -c "from backend.app.core.database import init_db; init_db()"
```

Persistent storage directories created:
- `./storage/uploads/` — Original uploaded host images
- `./storage/watermarked/` — Watermarked images embedded with DWT-SVD
- `./storage/keys/` — SVD transformation matrices & Arnold parameter keys (`.npz`)
- `./storage/attacked/` — Manipulated images generated by the Attack Simulator

## 5. Starting the Application

ProvenAI consists of two decoupled services: the **FastAPI Backend** (port 8000) and the **Vite React Frontend** (port 3000).

### Method A: Local Native Execution (Recommended for Development)

#### Terminal 1 — Start Backend Server:
```powershell
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
*Expected Output:*
```
INFO:     Started server process [PID]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

#### Terminal 2 — Start Frontend Server:
```powershell
cd frontend
npm run dev
```
*Expected Output:*
```
  VITE v5.4.x ready in 1050 ms
  ➜  Local:   http://localhost:3000/
  ➜  Network: use --host to expose
```

---

### Method B: Containerized Execution (Docker Compose)

To launch the entire isolated full-stack system via Docker:

```powershell
docker-compose up --build -d
```

- **Backend:** Accessible at `http://localhost:8000`
- **Frontend:** Accessible at `http://localhost:80`
- **Persistent Volume:** `provenai_storage` mapped to `/app/storage`

To inspect container logs:
```powershell
docker-compose logs -f
```

To stop containers:
```powershell
docker-compose down
```

## 8. Common Troubleshooting & Error Resolution

| Issue | Root Cause | Solution |
| :--- | :--- | :--- |
| `ValidationError: Extra inputs not permitted: vite_api_url` | Pydantic v2 rejects unexpected `.env` fields by default. | Fixed in `config.py` using `extra = "ignore"`. Ensure your backend files match the repository. |
| `InsecureKeyLengthWarning: The HMAC key is below minimum length` | JWT secret in `.env` is under 32 bytes. | Set `SECRET_KEY` in `.env` to at least 32 characters. |
| `ModuleNotFoundError: No module named 'cv2'` | OpenCV not installed. | Execute `pip install --user opencv-python-headless`. |
| `TypeScript TS2339: Property 'env' does not exist on type 'ImportMeta'` | Missing Vite environment typings. | Added `frontend/src/vite-env.d.ts` with `/// <reference types="vite/client" />`. |
| Port 8000 already in use | Another Uvicorn process is active. | Run `Stop-Process -Name python -Force` or use `netstat -ano \| findstr :8000` to locate and terminate the conflicting PID. |

## 9. Stopping the Application

- **Native Terminal:** Press `Ctrl + C` in each running terminal window.
- **Docker Compose:** Run `docker-compose down` from the project directory.
- **Kill Background Python Processes:**
  ```powershell
  Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force
  ```
